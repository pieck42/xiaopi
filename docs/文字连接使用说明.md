# 小皮文字连接 · 0.1

## 使用

1. 在 Cindy 安装并启用 `cindy-bridge/xiaopi-bridge-0.1.0.cindy`。
2. 点击小皮下方的“和小皮聊天”按钮，也可右键选择“和小皮聊天…”或在宠物窗口按 Ctrl+Enter。
3. 点击“连接 Cindy”。首次使用时在 Cindy 完成任务权限确认，创建“小皮 · 日常对话”。之后固定复用这个任务。
4. 在底部“在这里输入”的框中输入文字，点击“发送给小皮”或 Enter 发送，Shift+Enter 换行。上方按时间排列消息：你的消息靠右，小皮的回复靠左；拖动中间分隔条可调整上下区域。宠物会切换为处理、回答状态。本版不录音、不播报。
5. 任务如需授权或补充信息，请回 Cindy 原生任务界面处理。

Cindy 需要保持运行，插件需要启用。关闭聊天窗口只隐藏窗口，退出宠物才结束桌面进程；Cindy 里已接受的任务可以继续执行。

## 本地数据与隐私

- 任务绑定及不确定派发记录保存在 Cindy 插件自己的参数存储中，更新插件保留，卸载可能清除。
- 桌面待发送消息保存在项目 `.xiaopi/outbox.json`，确认发送受理后删除，不另存完整聊天历史。该目录已被 Git 忽略。
- 本地连接信息放在系统用户应用数据目录的 `Xiaopi/bridge.json`，含随机本地连接令牌，不应分享或提交。
- 本地服务只监听 `127.0.0.1`，使用随机令牌校验，拒绝网页 Origin 及非预期 Host；不提供局域网接口。这不防御拥有同一系统账号文件权限的其他程序。
- 文字会通过 Cindy 发送给任务使用的模型，费用和执行权限沿用其任务设置；安装时不自动发送对话。
- Node 工作进程拥有系统账号的原生权限，本实现只使用本地连接和上述连接信息文件；没有获取 Cindy 的模型密钥，也没有复制账号凭据。

## 重试与恢复

每条消息发送前保存固定编号。发送失败或响应丢失时，使用“重试原消息”，沿用同一请求键和首次派发版本；不要手动清除记录后重发可能已经执行的命令。

重启后恢复原任务。任务删除或会话状态不确定时显示错误，不悄悄新建、不换会话、不自动重新执行。现阶段没有取消任务按钮，用户可在 Cindy 停止。

## 开发与检查

```powershell
python build_bridge.py
node --test tests/bridge.test.cjs
python tests/chat_smoke.py
python xiaopi.py --smoke-test
```

`build_bridge.py` 合并 core.js 和 entry.js 到插件 main.js；修改后需要重新打包。开发检查需要 Node，安装后的插件使用 Cindy 自带 Node，不需要用户单独安装。

2026-10-15 已安装插件并完成本机真实联调：创建固定对话、发送一条测试文字，Cindy 返回 `XIAOPI_CONNECTED`，执行状态为 completed。随后重启插件，验证恢复同一 taskId、runId 和回复，没有再次调用模型。也通过了本机 HTTP 服务校验、SDK 模拟恢复与去重、真实 Tk 窗口及原有动画检查。

这验证了单轮真实收发与插件重启恢复；还没有做整机重启、长时间运行或多轮真实模型对话测试。

第一版每轮串行处理；回复以轮询获取。窗口显示最近 120 条文字消息；当前最多读取 2000 条历史记录，超过时提示在 Cindy 中查看。暂不支持接管已有任意会话、语音、跨设备连接和自动回复播报。
